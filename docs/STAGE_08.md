# Этап 08. Интерфейс Streamlit и графики Plotly

До этого этапа мы обращались к аналитику через терминал и `/docs`.
Теперь те же запросы можно выполнять в браузере: выбрать периоды,
посмотреть показатели и графики, задать вопрос, открыть историю
и скачать результат в JSON.

Короткая инструкция на английском — [Interface](instructions/interface.md),
архитектурное решение — [ADR 0008](adr/0008-streamlit-interface.md).
Фактические результаты проверок записаны в [VERIFICATION.md](VERIFICATION.md),
изменения — в [журнале разработки](DEVELOPMENT_LOG.md).

## 1. Что добавляет этап

На боковой панели выбери страницу `Dashboard`, `AI analyst`
или `Reports`. Интерфейс объединяет три задачи:

- **Панель показателей.** Выбрать текущий и предыдущий периоды, получить
  выручку, возвраты, число заказов и средний чек, увидеть динамику
  и вклад категорий или регионов.
- **AI-аналитик.** Отправить вопрос, прочитать факты и гипотезы,
  раскрыть доказательства и вызовы инструментов, открыть прошлый запуск.
- **Сохранённые отчёты.** Создать снимок сравнения периодов или поиска
  аномалий, открыть его из истории и скачать JSON.

Streamlit отвечает за элементы страницы, Plotly — за графики.
Формулы финансовых показателей остаются в PostgreSQL и Python `Decimal`.
Интерфейс не подключается к базе и не вызывает модель напрямую.

## 2. Как связаны браузер, интерфейс и API

```text
Браузер
   │ страница и действия пользователя
   ▼
Streamlit, 127.0.0.1:8501
   │ HTTP-запросы с датами или вопросом
   ▼
FastAPI, 127.0.0.1:8000
   ├── SQL / Decimal ──► PostgreSQL
   └── агент ──► mock или OpenAI ──► разрешённые инструменты
```

Это **два Python-процесса**. Команда запуска Streamlit не запускает
FastAPI, PostgreSQL и миграции. Поэтому нужны два терминала:
один для API, другой для интерфейса.

HTTP-клиент работает в Python-процессе Streamlit. Браузер показывает
результат, а не получает адрес базы и не выполняет SQL.
Ключ OpenAI настраивается для API по [этапу 07](STAGE_07.md);
вопрос в интерфейсе не содержит этот ключ.

## 3. Подготовка и запуск

Все команды выполняются из корня проекта, где находится `pyproject.toml`.
Если проект уже подготовлен и данные загружены, повторно генерировать
и загружать набор не нужно.

### Установить зависимости

```bash
uv sync --locked
```

Если `.env` ещё нет, создай его из примера:

```bash
cp .env.example .env
```

У существующего `.env` достаточно добавить новые настройки из примера.
Не заменяй свой файл без необходимости: в нём уже могут быть локальные
настройки базы и модели.

### Поднять базу и API

```bash
docker compose up --detach --wait db
uv run alembic upgrade head
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Для новой пустой базы сначала нужен набор данных. Как сгенерировать
20 000 учебных заказов и безопасно загрузить их, описано в
[Quickstart](instructions/quickstart.md). Загрузчик не перезаписывает
существующие строки.

Во втором терминале проверь готовность:

```bash
curl http://127.0.0.1:8000/ready
```

Ожидается `200` и `{"status":"ready","revision":"0003"}`.
`/health` подтверждает работу процесса, а `/ready` дополнительно
проверяет соединение с базой и миграции.

### Запустить интерфейс

```bash
uv run python -m streamlit run ui/main.py --server.address 127.0.0.1
```

Открой <http://127.0.0.1:8501>. Оставь оба терминала работающими.
Остановить процесс можно `Ctrl+C` в соответствующем терминале.

Если API слушает другой порт, укажи адрес интерфейсу перед запуском:

```bash
UI_API_URL=http://127.0.0.1:8001 \
  uv run python -m streamlit run ui/main.py --server.address 127.0.0.1
```

Запуск через `python -m streamlit` сохраняет корень проекта в пути
импортов, чтобы `ui/main.py` мог импортировать пакеты `ui` и `app`.

Номер порта Streamlit меняется отдельно: `--server.port 8502`.
Он не должен совпадать с портом API.

## 4. Настройки интерфейса

| Переменная | Назначение |
| --- | --- |
| `UI_API_URL` | Базовый адрес FastAPI; по умолчанию `http://127.0.0.1:8000` |
| `UI_REQUEST_TIMEOUT_SECONDS` | Тайм-аут сетевого ожидания; по умолчанию `150` секунд, от `1` до `600` |

Настройки берутся из переменных окружения и `.env`; переменная окружения
имеет приоритет. После изменения настроек перезапусти Streamlit.

Адрес должен использовать HTTP или HTTPS и хост `localhost`,
`127.0.0.1` или `[::1]`. Логин, пароль, строка запроса и фрагмент
после `#` не допускаются. Путь отсутствует или равен `/`: адрес
`http://127.0.0.1:8000/api` не подходит.
Неверная настройка показывается понятным сообщением, без вывода
содержимого `.env` или traceback.

Тайм-аут HTTP-клиента ограничивает сетевое ожидание, а не задаёт
гарантированный общий срок выполнения. Он отличается от лимита
времени агента. Если интерфейс перестал ждать ответ, уже отправленная работа на API может
продолжаться. Сначала проверь историю запусков: повторная отправка
создаёт новый запуск. Изменение `UI_REQUEST_TIMEOUT_SECONDS` не меняет
`AGENT_TIMEOUT_SECONDS` и не отменяет SQL-запрос.

## 5. Панель показателей

На странице `Dashboard` выбери границы текущего и сравнительного
периодов, измерение `category` или `region` и нажми `Load dashboard`.
Изменение полей само по себе не отправляет запрос: данные обновляются
после нажатия кнопки.
Для воспроизводимого учебного примера:

| Поле | Значение |
| --- | --- |
| Начало текущего периода | `2026-09-01` |
| Конец текущего периода | `2026-10-01` |
| Начало сравнения | `2026-08-01` |
| Конец сравнения | `2026-09-01` |

Конец **не входит** в период. Сентябрь — это `[2026-09-01, 2026-10-01)`,
а не период до 30 сентября включительно. Даты интерпретирует API
в часовом поясе `Europe/Moscow`.

Для сравнения категорий и регионов нужны оба периода. API отклоняет
пустые, перевёрнутые интервалы и интервалы длиннее 120 календарных
месяцев. Эти ограничения относятся к REST-аналитике; инструменты
агента имеют отдельное ограничение в 24 месяца.

Панель использует существующие маршруты:

| Данные | HTTP-запрос |
| --- | --- |
| Продажи, возвраты, чистая выручка и месячная динамика | `GET /api/metrics/revenue` |
| Оплаченные заказы и средний чек | `GET /api/metrics/orders` |
| Вклад категорий | `GET /api/analytics/categories` |
| Вклад регионов | `GET /api/analytics/regions` |

Параметры периода называются `start`, `end`, `compare_start`,
`compare_end`. Формулы не дублируются в интерфейсе.

### Как читать показатели

- **Оплаченные продажи** учитывают оплаченные позиции с учётом скидок.
- **Возвраты** относятся к дате обработки возврата.
- **Чистая выручка** — оплаченные продажи минус обработанные возвраты.
- **Средний чек** считается до возвратов; без оплаченных заказов он
  отсутствует, а не равен нулю.
- **Процент изменения** от нулевой базы не определён. API возвращает
  `null`, интерфейс не заменяет его выдуманными `0%`.

Подробные определения — в [этапе 04](STAGE_04.md).

### Графики и точные деньги

API передаёт деньги JSON-строками, например `"466678757.35"`.
Карточки, таблицы и выгружаемый JSON должны сохранять точное значение.
Plotly использует числовые координаты для положения линии или столбца;
это способ рисования, а не источник финансового расчёта.
Точное значение остаётся в подписи или подсказке графика и в JSON.
Панель показывает месячные ряды выручки и заказов и отдельный график
вклада выбранных групп.

Вклад категории — подписанная доля общего изменения. При противоположных
изменениях разных категорий доля может быть отрицательной или превышать
100%. Это не ошибка графика; объяснение есть в [этапе 04](STAGE_04.md).

Если выбраны месяцы вне набора, нулевой результат может быть правильным.
Проверь даты и наличие данных, прежде чем искать ошибку в интерфейсе.

Разные блоки панели загружаются отдельными HTTP-запросами. Каждый
ответ API согласован внутри своего снимка, но вся панель не является
одной транзакцией. Если продажи меняются между запросами, ответы
могут относиться к разным состояниям базы.

### Поиск аномалий и сохранение

Отдельная форма задаёт период поиска аномалий и `seed`. Учебные
значения — `2026-01-01`–`2026-10-01` и `42`. Запрос к детектору
не создаёт сохранённый отчёт сам по себе.

Явная команда сохранения вызывает `POST /api/reports`: API
**считает результат заново** и сохраняет его. Поэтому при изменении
данных он может отличаться от ранее загруженной панели. После
сохранения интерфейс показывает именно возвращённый снимок.

Параметры, отправленные вместе с запросом, сохраняются с результатом
в состоянии страницы. Если после загрузки изменить дату в форме,
но ещё не отправить её, выгрузка относится к прежнему показанному
результату, а не к неподтверждённым изменениям полей.

## 6. Вопрос AI-аналитику

На странице `AI analyst` введи вопрос в поле чата. Пример:

```text
Почему упала выручка в сентябре 2026 года?
```

Интерфейс отправляет ровно такое тело:

```json
{
  "question": "Почему упала выручка в сентябре 2026 года?"
}
```

Маршрут — `POST /api/agent/runs`. Вопрос должен содержать от 3 до
2 000 символов; после удаления пробелов по краям должно остаться
хотя бы 3 символа. Настройки модели,
названия инструментов и SQL в это тело не входят.

Успешный запуск возвращает `201 Created`. На странице можно прочитать:

- краткий ответ и факты;
- гипотезы, рекомендации и ограничения;
- ссылки на доказательства: `call_id`, путь `field` и точное `value`;
- цепочку инструментов и параметры запуска.

**Факт и гипотеза — разные вещи.** Проверка доказательств сопоставляет
значения с результатами инструментов и проверяет распознанные числовые
литералы. Она не доказывает причинную связь. Подробные границы проверки
разобраны в [этапе 07](STAGE_07.md).

### Демонстрационный и настоящий режим

По умолчанию API использует `LLM_PROVIDER=mock`. Это заранее заданный
план расследования с настоящими SQL-инструментами и проверкой отчёта,
без вызова языковой модели. Интерфейс показывает, какой провайдер
выполнил запуск.

Для настоящей модели настрой API по [инструкции агента](instructions/agent.md)
и перезапусти его. Наличие страницы чата само по себе не подтверждает
работу OpenAI: фактические проверки модели фиксируются отдельно.

### История вопросов не является памятью модели

Каждый отправленный вопрос создаёт **независимый запуск**.
История помогает открыть прошлый результат, но не добавляется
автоматически к следующему вопросу. Поэтому вместо «А что было до этого?»
пиши полный вопрос, например «Сравни август и июль 2026 года».

Запуски хранятся на стороне API в `agent_runs`, а не только во вкладке
браузера. Обновление страницы Streamlit не должно повторно отправлять
уже выполненный `POST`. Новую работу запускает явная отправка вопроса.

## 7. Сохранённые отчёты

Отчёт сравнения и запуск агента — разные сущности:

| Сущность | Где хранится | Содержимое |
| --- | --- | --- |
| Отчёт | `reports` | Параметры и готовый результат сравнения или поиска аномалий |
| Запуск агента | `agent_runs` | Вопрос, статус, отчёт или ошибка, цепочка инструментов |

На странице `Dashboard` можно создать сравнение или отчёт
аномалий, а на `Reports` — открыть сохранённый результат из списка.
Для сравнения выбери два периода и измерение — категории
или регионы. Пример тела `POST /api/reports`:

```json
{
  "kind": "comparison",
  "start": "2026-09-01",
  "end": "2026-10-01",
  "compare_start": "2026-08-01",
  "compare_end": "2026-09-01",
  "dimension": "category"
}
```

Для поиска аномалий нужен достаточно длинный период полных месяцев:

```json
{
  "kind": "anomalies",
  "start": "2026-01-01",
  "end": "2026-10-01",
  "seed": 42
}
```

Детекторы месячных аномалий пропускают неполные календарные месяцы.
Отдельный кандидат — повод для проверки, а не доказанная причина
изменения бизнеса. В интерфейсе нет доступа к `ground_truth.json`:
учебный ключ используется отдельной офлайн-проверкой этапа 05.

Созданный отчёт — **снимок**. После добавления новых продаж его числа
не меняются; живую панель можно загрузить заново. История отчётов
получается через `GET /api/reports`, выбранный результат — через
`GET /api/reports/<uuid>`. Списки истории постраничные: следующая
страница меняет `offset`, а не загружает всю историю сразу.

## 8. Скачать результат

Кнопка загрузки сохраняет JSON, полученный от API. В нём остаются UUID,
параметры, точные денежные строки и результат. JSON можно открыть
в редакторе или обработать программой; это не Excel-таблица и не PDF.

Скачанный JSON не запускает расчёт повторно. Графики не заменяют
исходные значения и не добавляют новую финансовую арифметику.
Сохраняй в Git только вымышленные учебные данные и результаты,
не реальные клиентские сведения и не ключи.

## 9. Ошибки и восстановление

| Что видно | Что проверить |
| --- | --- |
| API недоступен | Работает ли терминал Uvicorn, совпадают ли порт и `UI_API_URL` |
| База не готова, `503` | `docker compose ps`, ответ `/ready`, миграции и загрузку данных |
| Неверные параметры, `422` | Границы периода и полноту вопроса |
| Запись не найдена, `404` | UUID и подключение к той же базе, где сохранён результат |
| Агент не смог завершить ответ, `502` | Ограничения и историю запуска по `run_id`, если он был сохранён |
| Время ожидания истекло | Историю; запрос на API мог продолжить работу |
| Пустой список | В этой базе ещё может не быть сохранённых отчётов или запусков |

Интерфейс показывает заранее заданные понятные сообщения.
Он не выводит пользователю полный ответ ошибки сервера, traceback,
адрес базы или значение ключа. Полезную для диагностики информацию
смотри в терминале API, не копируя секреты в отчёт или переписку.

Операции создания не повторяются автоматически после ошибки или
перерисовки страницы. Это уменьшает риск дублей, но не делает
HTTP-запрос идемпотентным: повторное нажатие пользователем создаёт
новую запись.

## 10. Как устроен код

| Файл | Назначение |
| --- | --- |
| `ui/main.py` | Страницы Streamlit, формы, состояние показанного результата, история и загрузки JSON |
| `ui/config.py` | Настройки UI и проверка локального адреса API |
| `ui/client.py` | HTTP-запросы и разбор ответов по существующим схемам API |
| `ui/charts.py` | Графики Plotly из готовых аналитических ответов |
| `ui/models.py` | `DashboardSnapshot` и `ChatEntry`: типы сохранённого состояния между перезапусками страницы |

Клиент использует стандартную библиотеку `urllib`. Он не следует
перенаправлениям, не использует настройки сетевого прокси и не повторяет
запросы автоматически. Это делает локальный маршрут обращения явным.
Ответы разбираются типизированными схемами API; произвольный текст
ошибки сервера не становится пользовательским сообщением.

Streamlit перезапускает код страницы при действиях пользователя.
Поэтому введённые значения формы, отправленный запрос и уже
показанный результат различаются. `session_state` сохраняет
последний результат внутри пользовательской сессии; долговременная
история по-прежнему находится на API. В текущей сессии чата остаются
последние 20 записей. Списки истории API открываются страницами
по 10 записей; это не удаляет остальные сохранённые запуски.

## 11. Как проверить этап вручную

Используй вымышленный набор. Интеграционные тесты запускаются только
с явным `TEST_DATABASE_URL`, оканчивающимся на `_test`; правила из
[Testing](instructions/testing.md) продолжают действовать.

1. Подними API и Streamlit на локальных адресах. Проверь `/ready`.
2. Открой панель, сравни сентябрь с августом 2026 года.
3. Сопоставь точные значения с прямым ответом
   `GET /api/metrics/revenue` для тех же дат. Посмотри подписи графика.
4. Отправь полный вопрос в режиме `mock`; открой доказательства
   и цепочку инструментов. Проверь обозначение провайдера.
5. Найди этот запуск в истории и скачай JSON.
6. Создай отчёт сравнения и отчёт аномалий, открой их из списка
   и скачай каждый результат.
7. Перезагрузи страницу: без явной отправки не должно появиться
   нового запуска или отчёта.
8. Останови API и выполни запрос из интерфейса. Ожидается понятное
   сообщение об ошибке, без технических секретов. Снова запусти API.

Unit-тесты HTTP-клиента подставляют заранее заданные ответы API.
Проверки страниц через Streamlit `AppTest` тоже используют подменённый
клиент: можно проверить форму, состояние и отсутствие повторной
отправки без базы и ключа модели. Эти тесты не открывают настоящий
браузер и не доказывают работу сети.

Автоматические тесты и точные результаты текущего прогона перечислены
в [VERIFICATION.md](VERIFICATION.md). Работа через подменённый HTTP-клиент,
настоящий локальный браузер, реальная модель и удалённый GitHub Actions —
разные проверки; успешность одной не подтверждает остальные.

## 12. Ограничения

- Это локальный учебный интерфейс. Аутентификация и разграничение
  доступа пока не реализованы; API и Streamlit запускаются на loopback.
- История ограничена страницами API; список не сообщает общее число
  записей. Удаления результатов через API нет.
- Вопросы независимы: долговременной памяти диалога нет.
- Экспорт этого этапа — JSON. Автоматического PDF-отчёта по каждому
  запуску нет; PDF в `docs/guide/` объясняет проект.
- HTTP-тайм-аут интерфейса не гарантирует отмену работы API.
- Модель может неверно интерпретировать вопрос или причинность;
  доказательства и гипотезы нужно читать, а не только смотреть на график.

## 13. Проверь себя

1. Почему для интерфейса и API нужны два процесса?
2. Где вычисляется чистая выручка, а где рисуется её график?
3. Зачем хранить деньги строками, если график использует числа?
4. Чем история запусков отличается от памяти диалога?
5. Почему после тайм-аута сначала стоит проверить историю?
6. Почему сохранённый отчёт может отличаться от свежей панели?

<details>
<summary>Ответы</summary>

1. Streamlit отвечает за страницу, FastAPI — за аналитику, базу и агента.
   Интерфейс вызывает API по HTTP и не подменяет его.
2. PostgreSQL и Python `Decimal` вычисляют показатели; Streamlit
   отображает ответ, Plotly рисует координаты из готовых данных.
3. Строка сохраняет точное значение до копейки. Числовая координата
   нужна для рисунка, но не становится финансовым первоисточником.
4. История открывает сохранённый результат. Следующий запуск не получает
   автоматически предыдущие вопросы и ответы.
5. Работа на API могла продолжиться после прекращения ожидания клиентом.
   Повторная отправка может создать ещё один запуск.
6. Отчёт хранит снимок на момент создания, а панель запрашивает текущие
   данные. Новые продажи не переписывают сохранённый JSON.

</details>
