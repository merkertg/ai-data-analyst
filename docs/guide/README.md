# Наглядный PDF-гайд по AI Data Analyst

[← README проекта](../../README.md) · [Руководство этапа 01](../STAGE_01.md) · [Руководство этапа 02](../STAGE_02.md) · [Руководство этапа 03](../STAGE_03.md) · [CI/CD подробно](../CI_CD.md)

Руководство есть в двух одинаковых по содержанию версиях:

- [ai-data-analyst-guide.pdf](ai-data-analyst-guide.pdf) — на русском;
- [ai-data-analyst-guide-en.pdf](ai-data-analyst-guide-en.pdf) — на английском.

В каждой 31 страница: обложка и 28 разделов. Раздел 1 — обзор проекта.
Разделы 2–11 посвящены этапу 01: путь запроса, uv и lock-файл, импорт и
ловушка pytest, HTTP, разбор кода, настройки, тесты, Ruff и mypy, Git.
Разделы 12–20 — этапу 02: PostgreSQL в Docker, таблицы и связи, правила
целостности, деньги и время, SQLAlchemy, миграции Alembic, `/ready`, SQL
вручную, тесты с базой. Разделы 21–23 — этапу 03: воспроизводимые CSV, пять бизнес-аномалий,
эталон, безопасная загрузка и проверки качества. Разделы 24–28 общие:
CI, шпаргалка, типичные ошибки, вопросы для самопроверки и итоги проверки.

В английской версии отрывки кода показаны как есть, поэтому комментарии
в них на русском; учебные данные тоже содержат русские названия.

## Какие файлы составляют руководство

| Файл | Назначение |
| --- | --- |
| [ai-data-analyst-guide.pdf](ai-data-analyst-guide.pdf), [ai-data-analyst-guide-en.pdf](ai-data-analyst-guide-en.pdf) | Итоговые документы для чтения и показа |
| [verification.json](verification.json) | Фактические результаты проверки: дата, коммит, тесты, команды, ответы сервера, статус удалённого CI. Тексты — парами `{"ru": ..., "en": ...}` |
| [../../scripts/build_guide.py](../../scripts/build_guide.py) | Точка входа: обложка, колонтитулы, проверка JSON, сборка обеих версий |
| [../../scripts/guide/](../../scripts/guide/) | Модули гайда: `i18n.py` (язык и `tr()`), `layout.py` (шрифты, стили, блоки), `diagrams.py` (схемы), `sources.py` (данные проекта и записанные выводы), `toc.py` (оглавление), `stage01.py`, `stage02.py`, `stage03.py`, `story.py` (тексты разделов) |

Каждый текст в модулях задаётся парой `tr("русский", "english")`, поэтому
обе версии всегда имеют одинаковую структуру.

Часть данных генератор берёт прямо из проекта, а не из текста:

- код маршрутов, настроек, моделей и тестов — из файлов через `ast`;
- версии зависимостей и число пакетов — из `uv.lock`;
- число таблиц, ограничений и индексов — из моделей SQLAlchemy;
- OpenAPI-схема `HealthResponse` и пример JSON — из настоящего приложения;
- текст SQL-запроса 02 — из `sql/02_net_revenue_by_month.sql`.

Выводы команд, которым нужна запущенная база (psql, Alembic, `/ready`),
и результаты экспериментов этапа 01 записаны константами в
`scripts/guide/sources.py`. Те же числа проверяют интеграционные тесты.

## Как пересобрать

Нужен ReportLab 4.4.9. Он не входит в зависимости проекта:
`uv run --with` добавляет его только на время команды. Запуск из корня проекта:

```bash
uv run --locked --with 'reportlab==4.4.9' python scripts/build_guide.py
```

По умолчанию собираются обе версии. Одну версию:

```bash
uv run --locked --with 'reportlab==4.4.9' python scripts/build_guide.py --lang en
```

`--output` задаёт другой путь и работает только вместе с `--lang ru` или `--lang en`.

На Mac используются системные шрифты PT Sans и PT Mono из
`/System/Library/Fonts/Supplemental/`, на Linux — DejaVu Sans
(пакет `fonts-dejavu-core`). Если шрифты не найдены, сборка завершается
понятной ошибкой. Символов, которых нет в PT Sans (например `⇔`), в текстах
избегаем; стрелки `→ ← ↓` рисуются шрифтом PT Mono автоматически.

Старый PDF перед сборкой копируется во временную папку системы
(`<имя>-before-<дата-время>.pdf`). Новый файл сначала собирается рядом
во временный и заменяет PDF только при успехе.

## Как обновлять проверенные сведения

1. Выполни все проверки по [инструкции тестирования](../instructions/testing.md).
2. Запиши фактические результаты в `verification.json` на обоих языках:
   дату, коммит, числа тестов, команды и их результаты.
3. Статус GitHub Actions указывай отдельно. `not_verified` значит, что
   удалённый запуск не подтверждён. Локальный успех его не заменяет.
4. Пересобери обе версии и проверь каждую страницу (ниже).
5. Зафиксируй исходник, JSON, оба PDF и связанную документацию одним коммитом.

Генератор отклоняет JSON без обязательных полей, без одного из языков,
с отрицательными счётчиками или с `unit + integration ≠ total`,
`passed + failed + skipped ≠ total`.

## Как проверить PDF после сборки

```bash
pdfinfo docs/guide/ai-data-analyst-guide.pdf
mkdir -p /tmp/ai-data-analyst-guide-preview
pdftoppm -r 80 -png docs/guide/ai-data-analyst-guide.pdf /tmp/ai-data-analyst-guide-preview/ru
pdftoppm -r 80 -png docs/guide/ai-data-analyst-guide-en.pdf /tmp/ai-data-analyst-guide-preview/en
```

`pdfinfo` и `pdftoppm` входят в Poppler (`brew install poppler`). Проверь
каждую страницу обеих версий: кириллица и стрелки читаются, нет пустых
квадратиков, код и таблицы помещаются в поля, подписи схем не пересекаются,
заголовок не остаётся один внизу страницы. В английской версии не должно
быть русского текста вне отрывков кода и учебных данных:

```bash
pdftotext docs/guide/ai-data-analyst-guide-en.pdf - | grep -n '[А-Яа-яЁё]'
```

Сверь даты, число тестов и статус CI с `verification.json`. Успешная сборка
сама по себе не подтверждает качество вёрстки.


## Обновление этапа 03 (20 октября 2026 года)

Обе версии включают данные, аномалии A01–A05, загрузку и качество.
В сводке — 106 прошедших тестов (52 unit + 54 integration), полный
набор на 20 000 заказов и неподтверждённый удалённый CI. `base_commit`
указывает базовый коммит и рабочее дерево, а не новый коммит этапа 03.

В этой сессии ReportLab 4.4.9 взят из готового рабочего runtime Codex;
зависимости приложения не менялись. Все страницы обеих версий отрендерены
и просмотрены, новые разделы и итоги дополнительно проверены крупно.
PDF-файлы помечены как binary в `.gitattributes`, чтобы Git не показывал
их внутренние байты как текстовые изменения.
