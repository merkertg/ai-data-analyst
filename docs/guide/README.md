[Открыть руководство](ai-data-analyst-guide.pdf). 18 страниц: обложка
и 16 разделов этапа 01. Путь запроса, uv и lock-файл, импорт и ловушка
pytest, HTTP, разбор кода, настройки, тесты, Ruff и mypy, CI, Git,
шпаргалка, типичные ошибки, вопросы для самопроверки и итоги проверки.

## Какие файлы составляют руководство

| Файл | Назначение |
| --- | --- |
| [ai-data-analyst-guide.pdf](ai-data-analyst-guide.pdf) | Итоговый документ для чтения и показа |
| [verification.json](verification.json) | Фактические результаты проверки: дата, коммит, тесты, команды, ответы сервера, статус удалённого CI |
| [../../scripts/build_guide.py](../../scripts/build_guide.py) | Исходник макета, схем и текста |

Часть данных генератор берёт прямо из проекта, а не из текста:

- код `app/main.py`, `app/config.py` и фикстуры теста — из файлов;
- версии зависимостей и число пакетов — из `uv.lock`;
- шаги проверок — из `.github/workflows/ci.yml`;
- OpenAPI-схема `HealthResponse` и пример JSON — из настоящего приложения.

Поэтому после изменения кода достаточно пересобрать PDF. Вывод Ruff и mypy
в разделе 10 — записанные результаты экспериментов (константы в скрипте).

## Как пересобрать

Нужен ReportLab 4.4.9. Он не входит в зависимости проекта:
`uv run --with` добавляет его только на время команды. Запуск из корня проекта:

```bash
uv run --locked --with 'reportlab==4.4.9' python scripts/build_guide.py
```

На Mac используются системные шрифты PT Sans и PT Mono из
`/System/Library/Fonts/Supplemental/`, на Linux — DejaVu Sans
(пакет `fonts-dejavu-core`). Если шрифты не найдены, сборка завершается
понятной ошибкой.

Старый PDF перед сборкой копируется во временную папку системы
(`ai-data-analyst-guide-before-<дата-время>.pdf`). Новый файл сначала
собирается рядом во временный и заменяет PDF только при успехе.

## Как обновлять проверенные сведения

1. Выполни все проверки: `uv run pytest`, `uv run ruff check .`,
   `uv run ruff format --check .`, `uv run mypy app tests`.
2. Запиши фактические результаты в `verification.json`: дату, коммит,
   число тестов, команды и их результаты.
3. Статус GitHub Actions указывай отдельно. `not_verified` значит, что
   удалённый запуск не подтверждён. Локальный успех его не заменяет.
4. Пересобери PDF и проверь каждую страницу (ниже).
5. Зафиксируй исходник, JSON, PDF и связанную документацию одним коммитом.

Генератор отклоняет JSON без обязательных полей, с отрицательными
счётчиками или с `passed + failed + skipped ≠ total`.

## Как проверить PDF после сборки

```bash
pdfinfo docs/guide/ai-data-analyst-guide.pdf
mkdir -p /tmp/ai-data-analyst-guide-preview
pdftoppm -r 80 -png docs/guide/ai-data-analyst-guide.pdf /tmp/ai-data-analyst-guide-preview/page
```

`pdfinfo` и `pdftoppm` входят в Poppler (`brew install poppler`). Проверь
каждую страницу: кириллица и стрелки читаются, нет пустых квадратиков,
код и таблицы помещаются в поля, подписи схем не пересекаются, раздел
не переносит на новую страницу пару строк. Сверь даты, число тестов
и статус CI с `verification.json`. Успешная сборка сама по себе
не подтверждает качество вёрстки.
