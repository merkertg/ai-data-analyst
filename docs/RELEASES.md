# Версии и публикация образа

[← README](../README.md) · [CI/CD подробно](CI_CD.md)

Как проверенный образ попадает в GitHub Container Registry (GHCR), как
выпустить версию и как запустить готовый образ. Короткая английская версия —
[CI and delivery](instructions/ci-and-delivery.md), устройство pipeline —
[CI_CD.md](CI_CD.md).

## 1. Когда запускается публикация

| Событие | Что публикуется |
| --- | --- |
| Push в `main` | `ghcr.io/merkertg/ai-data-analyst:main` и `:sha-<7 символов коммита>` |
| Push тега `v1.2.3` | `:v1.2.3` и `:sha-<коммит>` |
| Pull request, ручной запуск | Ничего: только проверки |

Публикация идёт последним заданием и только если прошли все предыдущие:
тесты с покрытием, аудит зависимостей, сборка и smoke-проверка стенда.

## 2. Что проверяется до GHCR

1. Ruff, строгий mypy, миграции вверх, `alembic check` и откат.
2. Все тесты на настоящей PostgreSQL; покрытие строк и ветвей ≥ 90 %.
3. Аудит `uv.lock`: новая уязвимость или просроченное исключение — ошибка.
4. Сборка образа и проверка: UID 10001, нет pytest, Ruff, mypy и uv.
5. `docker compose up`: миграции, демо-данные, токен, API и интерфейс healthy.
6. `scripts/smoke_stack.py`: `/ready`, 401 без токена, точные числа сентября,
   ответ агента с доказательствами, история, здоровье интерфейса.
7. `down` + `up`: данные и токен сохранились, smoke повторён.

## 3. Публикуется именно проверенный образ

Задание `container` сохраняет собранный образ (`docker save`) как артефакт
на сутки. Задание `publish` загружает этот файл, ставит теги и отправляет его.
Повторной сборки нет: в GHCR попадают те же слои, что прошли smoke. Метка
`org.opencontainers.image.revision` указывает коммит, а
`org.opencontainers.image.source` связывает пакет с репозиторием — права
пакета наследуются от репозитория (приватный репозиторий → приватный пакет).

Права `packages: write` есть только у задания публикации; остальные
задания читают код.

## 4. Как выпустить версию

```bash
git switch main
git pull --ff-only
git tag -a v1.0.0 -m "AI Data Analyst 1.0.0: ten course stages"
git push origin v1.0.0
```

Тег должен иметь вид `vX.Y.Z` и указывать на коммит из истории `main`,
иначе публикация остановится на проверке тега. Занятый тег не
перезаписывают: исправление — новая версия, например `v1.0.1`.

## 5. Как запустить опубликованный образ

```bash
echo "$GITHUB_TOKEN" | docker login ghcr.io -u <пользователь> --password-stdin
APP_IMAGE=ghcr.io/merkertg/ai-data-analyst:v1.0.0 docker compose up --no-build
```

Для приватного пакета нужен токен GitHub с правом `read:packages`.
`--no-build` запускает стенд из опубликованного образа без локальной сборки.
Публикуется образ amd64; на Mac с Apple Silicon он работает через эмуляцию,
а `docker compose up --build` собирает родной arm64.

## 6. Что проверить при ошибке

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| `Validate version tag` упал | Тег не вида `vX.Y.Z` или не на `main` | Удалить локальный тег, создать правильный на коммите из `main` |
| `denied: permission_denied` при push | У workflow нет права на пакеты | В Settings → Actions → General разрешить Read and write для `GITHUB_TOKEN`, либо дать доступ пакету |
| `Audit runtime dependencies` упал | Новая уязвимость, истёкшее или лишнее исключение | См. [DEPENDENCY_UPDATES.md](DEPENDENCY_UPDATES.md) |
| Smoke упал на числах | Демо-набор или расчёт изменились | Сравнить с [VERIFICATION.md](VERIFICATION.md), запустить стенд локально |

## 7. Ограничения

- Образ не подписывается (cosign) и SBOM не прикладывается — в отличие от
  первого проекта; для учебного приватного репозитория это следующий шаг.
- Старые версии `:sha-…` в GHCR не удаляются автоматически.
- Публикуется только amd64.
